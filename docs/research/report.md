# ЛР 2 — обоснование актуальности ВКР

**Тема ВКР:** Разработка и экспериментальная оценка метода верификации структурированных поисковых запросов, формируемых большими языковыми моделями

**Автор или участники команды:** Сапожников Артём Александрович, группа К3440

**Вклад каждого участника при командной работе:** индивидуальная работа. ВКР выполняется на материале командного проекта SQL-HR; в ВКР входит личный вклад автора: формализация требований, правила построения стратегий поиска, верификатор, эталонная разметка и экспериментальная оценка.

### Выводы по обзору

Text-to-SQL хорошо изучен [8–11], но даже сильные LLM выдают синтаксически корректные и семантически неверные запросы, а оценка обычно идёт по результату выполнения, а не по соответствию намерению пользователя. Российские работы [1–4] посвящены дообучению и сжатию моделей и поисковым интерфейсам; проверка семантической корректности сгенерированных запросов в них не рассматривается.

Верификация вывода LLM активно развивается в 2025–2026 гг.: ограничение генерации [12, 14, 16, 19] и проверка после генерации [13, 15]. Эти методы работают с SQL или кодом, а не с промежуточным представлением требований, и не учитывают различие обязательных, предпочтительных и исключающих условий и допустимость их ослабления. Ослабление требований изучено в рекомендательных системах на основе ограничений [18], но без LLM.

Для поиска кандидатов это критично: синтаксически корректный запрос может потерять обязательное требование рекрутера или добавить несуществующее [5, 7]. Можно использовать: эталонную разметку и метрики точного совпадения [8], правила проверки ограничений [15, 16], идеи ослабления требований [18], ручную разметку вместо LLM-оценщика [17]. Нерешённым остаётся метод, который проверяет соответствие структурированных условий исходному намерению и строит стратегии поиска с контролируемым ослаблением.

## 3. Обзор и сравнение аналогов

### Прямые аналоги

- **SQLens** (https://neurips.cc/virtual/2025/poster/116009) — обнаружение и исправление семантических ошибок в SQL, сгенерированном LLM, после генерации. Ограничения: проверяет SQL, а не требования пользователя; не различает типы требований; не формирует стратегии поиска.
- **PV-SQL** (https://arxiv.org/abs/2604.17653) — извлечение ограничений из вопроса и проверка SQL правилами. Ограничения: те же — объект проверки SQL, нет ослабления условий.
- **ChopChop** (https://doi.org/10.1145/3776708) — семантические ограничения во время генерации кода. Ограничения: требует доступа к токенам модели, неприменим к LLM через API; ориентирован на код.

### Косвенные аналоги

- **Структурированный вывод по JSON Schema** (OpenAI Structured Outputs, Outlines, Pydantic; https://github.com/dottxt-ai/outlines) — гарантирует корректность структуры и типов. Ограничения: не проверяет смысл и согласованность условий.
- **SQL-HR (исходная версия)** — LLM компилирует запрос в QuerySpec и формирует три стратегии Ideal/Fit/Fallback. Ограничения: стратегии генерируются независимо, без формальных правил; качество компиляции не измеряется.

### Таблица сравнения

**Почему выбраны эти критерии:** критерии отражают три уровня корректности, которые разделяет исследование (структура, непротиворечивость, соответствие намерению), специфику поиска (типы требований, ослабление, согласованность стратегий), а также практические ограничения: работу с моделями через API и наличие оценки влияния на результат поиска.

### Выводы по сравнению

Из существующих решений можно использовать: идею проверки после генерации и правила проверки ограничений (SQLens, PV-SQL), валидацию структуры по JSON Schema как первый уровень проверки, исходную архитектуру SQL-HR как основу реализации. Ни одно решение не сочетает проверку соответствия намерению с семантикой типов требований и контролируемым ослаблением условий. Ограничения, которые планируется устранить: независимая генерация стратегий без гарантий согласованности, отсутствие различия обязательных и ослабляемых требований, отсутствие измерения качества компиляции и её влияния на поиск.

## 4. Итоги

**Итоговая тема ВКР:** Разработка и экспериментальная оценка метода верификации структурированных поисковых запросов, формируемых большими языковыми моделями

**УДК для тезиса:** 004.8 (искусственный интеллект); дополнительно 004.65 (базы данных)

**Ключевые слова:** большие языковые модели, структурированные запросы, верификация, семантическая корректность, Text-to-SQL, поиск кандидатов, ограничения поиска, ослабление требований

### Актуальность исследования

LLM всё чаще служат интерфейсом к базам данных [9, 10], в том числе в кадровых системах [1, 6], где данные нельзя передавать во внешние сервисы. Ошибка преобразования запроса пользователя в структурированные условия незаметна: запрос выполняется, но теряет обязательное требование или добавляет несуществующее [5], и пользователь получает неверный результат без предупреждения. Для подбора персонала это особенно важно из-за рассогласованности требований вакансий и резюме [7]. Методы проверки 2025–2026 гг. [13–16] работают с SQL и кодом и не учитывают семантику требований и их ослабление. Рецензирование статьи о SQL-HR прямо указало на отсутствие оценки и контроля этого этапа.

### Цель исследования

Разработать и экспериментально оценить метод верификации структурированных поисковых запросов, полученных из естественного языка, включающий проверку семантических ограничений, выявление противоречий и формирование согласованных стратегий поиска с контролируемым ослаблением требований.

### Задачи исследования

1. Проанализировать подходы к генерации и верификации структурированных запросов с помощью LLM.
2. Формализовать требования пользователя (обязательные, ослабляемые, предпочтительные, исключающие) и определить классы ошибок компиляции: нарушение структуры, противоречия условий, несоответствие намерению.
3. Разработать правила построения стратегий Ideal/Fit/Fallback из исходных требований с сохранением семантических инвариантов и явной пометкой ослаблений.
4. Реализовать верификатор структурированных запросов в составе системы SQL-HR.
5. Подготовить эталонную разметку требований для 160 запросов с разбиением на наборы для разработки и тестирования по вакансиям.
6. Экспериментально оценить качество компиляции двух LLM, эффект верификации и её влияние на качество поиска в сравнении со структурным бейзлайном без LLM.

### Датасеты и сервисы

- **Данные SQL-HR** (внутренние): 44 744 русскоязычных резюме — используются внутри проекта, корпус без открытой лицензии; 40 вакансий из открытого API hh.ru; 160 запросов рекрутера в четырёх стилях; разметка релевантности 2 383 пар «запрос — кандидат». Назначение: основной экспериментальный материал.
- **Собственный датасет ВКР** (создаётся): эталонная разметка требований (QuerySpec) для 160 запросов. Назначение: прямая оценка качества компиляции и верификации.
- **Открытые бенчмарки Text-to-SQL:** Spider (https://yale-lily.github.io/spider), BIRD (https://bird-bench.github.io), PAUQ (https://aclanthology.org/2022.findings-emnlp.175). Назначение: методика разметки и метрик, сопоставление с общей задачей.
- **Сервисы:** API вакансий hh.ru (https://api.hh.ru); локальный запуск LLM (llama.cpp) и LLM через API для сравнения двух конфигураций.
